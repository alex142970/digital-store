# Digital Store

Магазин цифровых товаров

**[Живая версия](https://test-digital-store.hive01.ru)** ·
[Документация API](https://test-digital-store.hive01.ru/docs) ·
[Админка](https://test-digital-store.hive01.ru/admin.html)

## Возможности

- Витрина: каталог, поиск, меню категорий, баннер-карусель, блок пополнения Steam
- Покупка: заказ → оплата (вебхук-заглушка) → автоматическая выдача ключа → страница статуса
- Однократная выдача под гонками: двойной клик, повторные и параллельные вебхуки
- Админка: заказы, ручная повторная выдача, пополнение пула ключей активации
- Промокоды с лимитом использований, скидку считает сервер

## Стек

| Слой      | Решение                             |
| --------- | ----------------------------------- |
| Backend   | Node.js 24, Fastify 5, TypeScript   |
| Хранилище | PostgreSQL 18                       |
| Frontend  | HTML, CSS, нативные ES-модули       |
| Контракт  | OpenAPI 3.1                         |
| Тесты     | Vitest + Testcontainers, Playwright |

**Spec first подход.** `openapi.yaml` — источник истины, из него берутся:

- валидация входа и сериализация ответов (`fast-json-stringify`);
- типы TypeScript (`openapi-typescript`).

CI отдельным шагом перегенерирует типы и падает, если они разошлись со спецификацией, —
контракт не может незаметно разъехаться с кодом.

## Быстрый старт

```bash
docker compose up --build
```

Поднимет PostgreSQL, применит миграции, зальёт каталог и ключи, запустит приложение на
http://localhost:3000

Локально, без контейнера приложения:

```bash
docker compose up -d db
cp .env.example .env
npm ci
npm run migrate && npm run seed
npm run dev
```

## Однократная выдача

Ключ выдаётся ровно один раз, даже если по заказу одновременно прилетело полсотни
событий. Гарантии дают ограничения базы и атомарные переходы.

| Сценарий                     | Механизм                                                                   |
| ---------------------------- | -------------------------------------------------------------------------- |
| Двойной клик «Купить»        | Уникальный `idempotency_key` заказа - повтор возвращает существующий заказ |
| Повторный вебхук             | `event_id` — первичный ключ таблицы событий, повтор не применяется дважды  |
| Параллельные вебхуки         | Условный апдейт `update ... where status = ...`                            |
| Гонка за последний ключ      | `select ... for update skip locked`                                        |
| Таймаут поставщика           | Детерминированный `request_id = req_<order_id>` и кэш выданных кодов       |
| Одновременный повтор запроса | Транзакционная advisory-блокировка по `request_id`                         |

## Сбои и восстановление

`out_of_stock` и `delivery_failed` — восстановимые состояния. Из них заказ
возвращается тремя путями: фоновым обработчиком, повторным вебхуком или кнопкой в
админке. Любой из них идемпотентен.

Неоплаченные заказы истекают по таймауту и возвращают занятый промокод в оборот, иначе
брошенная корзина навсегда съедала бы лимит.

## Промокоды

Лимит держится одним атомарным запросом:

```sql
update promocodes set used_count = used_count + 1
where code = $1 and used_count < max_uses
```

## API

| Метод  | Путь                               | Назначение                    |
| ------ | ---------------------------------- | ----------------------------- |
| `GET`  | `/api/products`                    | Каталог                       |
| `POST` | `/api/orders`                      | Создать заказ                 |
| `GET`  | `/api/orders/{id}`                 | Статус заказа                 |
| `POST` | `/api/orders/{id}/pay`             | Эмуляция оплаты, шлёт вебхук  |
| `POST` | `/webhook/payment`                 | Приём события об оплате       |
| `POST` | `/internal/providers/{a\|b}/issue` | Заглушки поставщиков          |
| `GET`  | `/api/admin/orders`                | Заказы, включая незавершённые |
| `POST` | `/api/admin/orders/{id}/retry`     | Повторная выдача              |
| `POST` | `/api/admin/keys`                  | Пополнить пул                 |
| `GET`  | `/api/admin/promocodes`            | Расход лимитов                |

Интерактивная документация — `/docs`, спецификация — `/openapi.json`.

## Тесты

```bash
npm test          # интеграционные, поднимают PostgreSQL через Testcontainers
npm run test:e2e  # e2e в браузере
npm run race      # состязательные сценарии
```

Интеграционные тесты работают с базой в контейнере, а не с моками:
проверяются именно те ограничения и блокировки, на которых держатся гарантии. e2e
поднимают тот же серверный процесс, что и в бою, и ходят по интерфейсу как пользователь.

### Проверка гонок

`npm run race` требует запущенного приложения и гоняет по 50 параллельных запросов на
сценарий:

```
- двойной клик «Купить»: один заказ на все параллельные запросы
- параллельные вебхуки «оплачено»: одна выдача, один ключ, все ответы 200
- один event_id доставлен многократно: событие сохранено и применено один раз
- вебхук по несуществующему заказу: принят и сохранён, не потерян
- все заказы борются за последний ключ: выдан ровно один
- пополнение пула под нагрузкой: ровно один застрявший заказ получает ключ
- промокод с лимитом 3 под параллельными запросами: применён ровно 3 раза
```

Скрипт создаёт свой товар, убирает его за собой и завершается ненулевым кодом при любом
расхождении. Число параллельных запросов меняется через `RACE_CONCURRENCY`.

## Переменные окружения

Все значения имеют разумные значения по умолчанию, обязателен только `DATABASE_URL`.
Полный список — в `.env.example`.

| Переменная                                         | Назначение                                |
| -------------------------------------------------- | ----------------------------------------- |
| `DATABASE_URL`                                     | Строка подключения к PostgreSQL           |
| `PROVIDER_A_ERROR_RATE`, `PROVIDER_A_TIMEOUT_RATE` | Доля отказов и таймаутов поставщика A     |
| `PROVIDER_B_ERROR_RATE`, `PROVIDER_B_TIMEOUT_RATE` | То же для резервного поставщика           |
| `DELIVERY_SWEEP_INTERVAL_MS`                       | Период фоновой дообработки                |
| `ORDER_EXPIRES_AFTER_MS`                           | Через сколько истекает неоплаченный заказ |

Доли отказов настраиваются, чтобы воспроизводить сбойные сценарии: выставьте единицу и
увидите ветку восстановления.

```
tests/integration/    против настоящей базы
tests/e2e/            сквозные, Playwright
scripts/race.ts       состязательные сценарии
```
